# Agent Skill 与 CLI PRD

## 1. 需求目标

让已知 WorkDailyAgent GitHub 地址的 macOS 用户可通过 CLI 安装中文 Agent Skill、启动应用，并让 Agent 查询本机工作记录、展示行为轨迹、生成和保存日报。

## 2. 用户能力

| 操作 | 默认结果 | 是否修改数据 |
|------|----------|--------------|
| 安装 Skill | 从 GitHub 安装 `work-daily-agent` | 只写 Skill 目录 |
| 检查环境 | 返回平台、工具链、数据库和应用通道状态 | 否 |
| 准备项目 | 按需克隆源码并安装依赖 | 写入托管源码和依赖目录 |
| 启动应用 | 直接启动 Tauri 桌面端 | 沿用应用现有行为 |
| 查询记录 | 单日返回事件 JSON，多日按日写入本地文件 | 否 |
| 查询 Agent 上下文 | 单日返回完整数据，多日默认返回摘要 | 否 |
| 展示行为轨迹 | 单日生成自包含 HTML，多日生成可离线打开的轨迹目录 | 只写导出文件 |
| 自定义轨迹样式 | 单次使用，用户要求时可保存或设为默认 | 按用户指令写本机模板 |
| 生成单日日报 | Agent 基于精简原始记录撰写、保存到应用并直接回答 | 写日报表，不生成文件 |
| 生成多日总结 | Agent 基于跨批次应用标题聚合结果撰写并直接回答 | 默认不保存 |
| 查询历史日报 | 返回日报列表或单条内容 | 否 |

## 3. 交互规则

1. 查看行为轨迹和生成日报是两个独立操作。
2. 行为轨迹默认生成与应用内活动分析页类似的两段式时间轴、环形占比和可展开明细。
3. 用户指定一次性样式时，不保存模板；明确要求保留时才保存。
4. 用户说“以后都用”时，将已保存样式设为默认。
5. 单日日报生成后默认写入 `reports` 表并直接回答，但不生成 Markdown；多日总结默认只回答、不保存。只有用户明确要求导出时才创建 Markdown。
6. Agent 只能使用记录中出现的信息，不将窗口标题推断为已完成成果。
7. 日期范围的首尾日期都包含在结果中，不限制总查询天数。
8. 多日轨迹在 7 天以内默认展开，超过 7 天默认折叠，用户可显式覆盖。
9. 默认多日展示不调用大模型；只有日报、记录分析或自由描述的新样式需要 Agent 理解生成。
10. Agent 必须将用户的完整日期范围传给一次多日 CLI 命令，不按内部 7 天查询批次拆分命令或输出页面。
11. 生成单日日报时只向 Agent 返回必要的原始事件字段，不重复返回行为轨迹块和应用明细；生成多日总结时逐批按应用标识和窗口标题聚合并跨批次合并。

## 4. 数据新鲜度

- 应用正在运行时，CLI 优先通过应用的本机通道查询，包含已落库、待落库和当前进行中的事件。
- 应用未运行时，CLI 只读 SQLite 数据库。例如用户从 `10:00` 开始在 Xcode 中编辑，该活动到 `10:18` 仍未结束，而采集器还没有将它闭合写入数据库，直读 SQLite 时会缺少这 `18` 分钟。CLI 必须在查询当天时返回明确警告。

## 5. 兼容与安全

- 仅支持 macOS 12 及以上。
- 不读取、输出或修改 API Key。
- 不提供清空活动记录、修改黑名单或管理系统权限的 CLI 命令。
- 单日 HTML 默认自包含；多日轨迹只读取同一导出目录中的本地资源，两者都不请求外部资源。
- 模板只保存布局和样式，不保存工作记录。
- CLI 内部每个 SQLite 查询批次最多读取 7 个自然日，日期范围总长度不受该批次大小限制；每天的完整轨迹数据独立写入本地私有文件。

## 6. 验收标准

1. 可从 GitHub 仓库路径识别并安装 Skill。
2. 可通过一条 `npx` 命令进入 CLI 并启动项目。
3. Skill 的名称、说明、操作路由和默认提示为中文。
4. CLI 在应用运行时可查到当前进行中的事件，应用未运行时可降级直读数据库。
5. 默认轨迹 HTML 可离线打开，自定义样式可单次使用或保存复用。
6. 日报与轨迹分别执行；单日日报默认保存到应用但不生成文件，多日总结默认不保存，两者均直接回答。
7. 新增能力不影响现有页面、采集、黑名单、密钥和应用内日报功能。
8. `events`、`context`、`report context` 和 `timeline show` 支持用户完整范围的单次 `--from/--to` 调用，CLI 内部按 7 天分批且范围汇总时长无重复。
9. 多日 HTML 可离线打开，通过共享渲染器按日加载明细，不将全范围事件嵌入首页。
10. `report context --date` 不包含 `activity_blocks` 或 `usage`；范围模式返回跨批次合并后的应用标题聚合结果，且查询不写入 `reports` 表。
