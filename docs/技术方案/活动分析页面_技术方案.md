# 活动分析页面技术方案

## 1. 实现范围

新增独立的“活动分析”页面，实现按日期查询、行动轨迹可视化和应用使用占比。不修改现有“时间轴”和“日报/周报”页面的功能与展示。

## 2. 现有基础

- 前端使用 React + TypeScript，通过 Tauri `invoke` 调用 Rust 命令。
- 现有 `query_events(date)` 命令已支持按本地自然日查询事件。
- 查询结果已按当天 `00:00–24:00` 裁剪跨天事件，并合并尚未落库的待写事件和当前进行中事件。
- 每条事件已包含 `start_ts`、`end_ts`、`app`、`bundle_id`、`window_title`、`duration_ms` 和 `ongoing`。
- 本功能默认复用现有查询命令，不新增数据表，不修改事件写入逻辑。

## 3. 整体数据流

```text
选择日期
  → query_events(date)
  → 事件升序整理
  → 合并相邻的同应用记录
  → 生成行动轨迹数据
  → 生成应用时长聚合数据
  → 渲染时间轴、环形图和应用列表
```

行动轨迹和应用占比共用同一次查询的原始事件，但分别建模：轨迹数据使用 30 秒展示阈值，占比数据使用未过滤的完整事件。

## 4. 前端页面结构

- 在页面类型和左侧导航中新增 `activity` 项。
- 新页面维护独立的选中日期、事件数据、加载状态和错误状态。
- 日期变化时重新调用 `query_events`，一次查询同时驱动行动轨迹和应用占比。
- 所选日期为当天时定时刷新数据，使进行中事件的色块和占比随时间更新；历史日期只在进入页面或切换日期时查询。
- 页面使用现有 CSS 变量、字体、边框、圆角和按钮样式，保持与现有界面一致。

## 5. 行动轨迹建模

### 5.1 事件整理

1. 将查询结果按 `start_ts` 升序排列。
2. 使用 `bundle_id` 作为应用的主要识别字段；系统空闲事件使用固定空闲标识。
3. 仅当两条记录应用相同且时间相邻时，将其合并为一个外层应用轨迹块。
4. 每条原始记录作为外层轨迹块内的窗口标题分段，保留原始起止时间。
5. 公共查询层会合并相互重叠或相邻的系统空闲区间；系统空闲与普通应用事件重叠时，以普通应用事件为准裁剪空闲区间。原始数据库记录保持不变。

### 5.2 30 秒展示阈值

1. 先完成同应用相邻记录的合并，再以外层轨迹块的 `end_ts - start_ts` 判断是否展示。
2. 持续时间小于 30 秒的外层轨迹块不渲染；持续时间等于或大于 30 秒的轨迹块正常渲染。
3. 合并和过滤只执行一次。被过滤轨迹块前后的记录不再次合并，从而保留被过滤时段的空白。
4. 过滤仅作用于外层应用轨迹块，内部窗口标题分段不使用 30 秒阈值。
5. 跨越 `12:00` 的轨迹块先根据完整持续时间判断是否过滤，确认保留后再拆分到两行时间轴，避免各子段被重复过滤。

### 5.3 半日轨迹拆分

- 将每个需要展示的应用轨迹块与 `00:00–12:00` 和 `12:00–24:00` 两个区间分别求交集。
- 只为交集时长大于 0 的区间生成渲染块。
- 外层应用块和其内部标题分段使用相同的边界裁剪规则。

## 6. 时间轴渲染

每行时间轴表示 12 小时，固定为 `43,200` 秒。轨迹容器使用相对定位，色块使用绝对定位。

```text
leftPercent  = (segmentStart - rangeStart) / 43,200 × 100%
widthPercent = (segmentEnd - segmentStart) / 43,200 × 100%
```

- 位置和宽度始终使用时间比例计算，不根据文本长度改变色块宽度。
- 应用块只显示应用名，内部标题块只显示窗口标题。
- 文本使用单行省略显示。色块实际宽度低于文本展示所需的最小宽度时，隐藏文本但保留色块。
- 聚合应用块达到隐藏应用名的容器宽度时，同时将标题分段容器的上边界调整为父块上边界，使子色块占满父块高度。
- 时间刻度和轨迹块使用同一容器宽度，避免刻度与数据位置偏移。

## 7. 悬浮详情

- 应用块和内部标题块共用悬浮详情组件。
- 详情内容包含应用名、完整窗口标题、起止时间和持续时长。
- 悬浮层渲染到时间轴容器外的独立浮层中，并根据窗口边界调整方向，避免被轨迹容器裁剪或超出页面。

## 8. 应用时长聚合

1. 使用查询返回的未过滤事件计算，不使用行动轨迹过滤后的数据。
2. 按应用标识汇总 `duration_ms`，系统空闲作为独立应用项汇总。
3. 分母为全部事件 `duration_ms` 之和，单个应用占比为该应用时长除以分母。
4. 环形图使用 SVG 绘制，不增加图表依赖。
5. 环形图和列表共用同一份聚合数据和颜色映射，保证图表与列表一致。
6. 聚合时在每个应用项中保留未过滤的原始事件明细，按持续时长降序排列，时长相同时按起始时间升序排列。
7. 应用行作为独立的展开/收起按钮，展开时渲染窗口标题、起止时间和持续时长；多个应用可同时展开。
8. 百分比通过统一格式化函数输出，环形图标签和列表均保留两位小数。

## 9. 颜色映射

- 系统空闲固定使用灰色。
- 普通应用根据 `bundle_id` 生成稳定的颜色索引，保证同一应用在不同日期的颜色一致。
- 同一应用内的不同窗口标题在应用主色基础上使用不同明度，不改变应用所属色系。

## 10. 性能与影响范围

- 排序复杂度为 `O(n log n)`，合并、拆分、过滤和聚合均为 `O(n)`，按天查询的数据量不会形成明显性能压力。
- 不修改 SQLite 表结构、事件采集周期和日报生成入口。
- 合并引擎维护已记录时间水位，存储层只写入尚未覆盖的空闲区间，公共查询层统一归一化历史空闲重叠数据。
- 查询归一化结果由原时间轴、活动分析页面和日报生成共用，避免不同入口统计口径不一致。

## 11. 风险与处理

| 风险 | 处理方式 |
|------|----------|
| 效果图无精确尺寸标注 | 以效果图为视觉基准，在固定参考窗口尺寸下截图对照，同时使用响应式约束保证其他尺寸可用 |
| 30 秒轨迹过滤导致轨迹与占比不完全对应 | 轨迹只做展示过滤，占比始终使用完整数据，保证统计准确 |
| 隐藏短事件后误合并前后应用 | 先合并、再过滤，过滤后不再执行合并 |
| 跨 `12:00` 事件被分段过滤 | 先以完整轨迹块判断 30 秒阈值，再拆分渲染 |
| 悬浮层被时间轴裁剪 | 使用独立浮层并根据窗口边界调整显示位置 |
| 未授予 Accessibility 权限时窗口标题缺失 | 仍渲染应用轨迹块，不生成有效标题文本 |
| 当天进行中事件的宽度持续变化 | 仅在数据刷新时更新建模结果，使用稳定轨道尺寸避免页面跳动 |
| 系统最后活动时间未更新导致重复空闲区间 | 合并引擎使用单调时间水位限制空闲起点，存储层拒绝重复覆盖区间 |
| 历史空闲数据已经重叠 | 公共查询层合并空闲区间并扣除普通应用覆盖时间，不直接改写数据库 |

## 12. 验证方案

### 12.1 数据处理验证

- 相邻同应用、不同标题正确合并为一个外层块。
- `29` 秒应用块被过滤，`30` 秒应用块保留。
- 被过滤块前后的同应用块不合并。
- 跨 `12:00` 且总时长达到 30 秒的块在两行时间轴中均正确显示。
- 空闲事件计入应用占比，被轨迹过滤的事件仍计入占比。
- 无新输入时反复睡眠、唤醒不会重复生成历史空闲区间。
- 应用重启后从数据库恢复时间水位，不会重新补录已记录区间。
- 历史嵌套空闲区间合并为时间并集，与普通应用重叠的部分从空闲中扣除。

### 12.2 界面验证

- 时间刻度与色块起止位置对齐。
- 应用块和标题块的宽度与对应时长比例一致。
- 长标题单行截断，过窄色块不显示文本。
- 聚合色块隐藏应用名时，内部标题子色块占满父块高度。
- 悬浮详情显示完整内容，在页面边缘不被裁剪。
- 环形图、应用列表和颜色映射一致。
- 每个应用均可独立展开、收起事件明细，明细按持续时长降序展示。
- 环形图和应用列表中的百分比均保留两位小数。
- 日期切换后两个区域同步更新，现有其他页面表现不变。

### 12.3 工程验证

- 前端构建和静态检查通过。
- Rust 现有测试全部通过。
- 使用固定测试数据在参考窗口尺寸下截图，与 PRD 效果图对照验收。
