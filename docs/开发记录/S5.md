## 2. 具体变更

### 2.1 项目结构

```
code/src-tauri/src/
├── lib.rs              # +黑名单/清空/权限/活跃应用命令 + seed_default_blacklist
├── storage.rs          # +BlacklistRow + get/add/remove_blacklist + clear_all_data
└── collector/mod.rs    # 黑名单改为从 SQLite 加载 + 30s 定时刷新

code/src/
├── App.tsx             # +SettingsPage 组件 + "正在记录" banner
└── App.css             # +设置页样式（权限/黑名单/危险区）
```

### 2.2 关键代码变更

**storage.rs — 黑名单 CRUD + 数据清空**

- `BlacklistRow`：serde::Serialize，返回前端
- `get_blacklist()` → `Vec<BlacklistRow>`（按创建时间倒序）
- `add_blacklist(bundle_id, app_name)`：`INSERT OR IGNORE`（bundle_id 唯一）
- `remove_blacklist(bundle_id)`：按 bundle_id 删除
- `clear_all_data()`：事务删除 events + reports，blacklist 保留

**collector/mod.rs — 黑名单动态生效**

- 移除硬编码黑名单，改为 `reload_blacklist()` 从 SQLite 加载
- 启动时调用一次
- 新增 `blacklist_ticker`（30s），定期重新加载，使设置页增删实时生效
- `tokio::select!` 三路复用：3s 轮询 + 10s flush + 30s 黑名单刷新

**lib.rs — 新增 Tauri 命令**

| 命令 | 功能 |
|------|------|
| `get_blacklist` | 查询全部黑名单 |
| `add_blacklist(bundle_id, app_name)` | 添加黑名单项 |
| `remove_blacklist(bundle_id)` | 删除黑名单项 |
| `clear_all_data` | 清空 events + reports |
| `check_accessibility` | 检测 Accessibility 权限状态 |
| `open_accessibility_settings` | deep link 跳系统设置辅助功能页 |
| `get_active_app_info` | 获取当前活跃应用名 + 标题（供"正在记录"展示） |

- `seed_default_blacklist()`：首次启动时（blacklist 表为空）填充 3 个默认项（1Password / 钥匙串 / 安全代理）

**前端 — 设置页 + 正在记录 banner**

`SettingsPage` 组件：
- **辅助功能权限**：状态标签（已授权/未授权）+ "去授权"按钮 → `open_accessibility_settings`
- **黑名单管理**：列表（应用名 + bundle_id + 删除按钮）+ 添加输入框（bundle_id + 应用名）
- **数据管理**：红色危险区，`confirm()` 二次确认后清空

`TimelinePage` 新增"正在记录"banner：
- 采集中：紫色 banner 显示 `正在记录：{app_name} - {window_title}`，3s 轮询更新
- 已暂停：灰色 banner 提示"采集已暂停"

## 4. 遇到的问题与解决

### 4.1【设计决策】黑名单动态生效方案

- 问题：设置页增删黑名单后，采集模块需要感知变化。
- 方案对比：① 共享 `Arc<RwLock<Vec<String>>>` ② 采集模块定期重新读 DB
- 选择方案 ②：每 30s 从 SQLite 重新加载。理由：简单、无锁竞争、30s 延迟可接受（黑名单不是高频操作）。如需实时生效，S6 可改为方案 ① + Tauri 事件通知。

### 4.2【已知】macOS IME 噪音日志

- 终端持续输出 `_TIPropertyValueIsValid` / `imkxpc_setApplicationProperty`，属 macOS 输入法框架噪音，与应用无关，无法消除，可忽略。
