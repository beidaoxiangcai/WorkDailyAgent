## 3. 实现要点

1. Keychain 项固定使用 `com.workdaily.agent.llm / deepseek-api-key`。
2. 保存流程为“候选 Key 最小请求验证 → 验证成功 → 写入 Keychain”。
3. 状态命令仅返回 `configured`、`source` 和 `lastFour`。
4. `API_KEY_NOT_CONFIGURED` 只用于前端识别配置缺失，不包含敏感信息。
5. 未配置提醒采用“取消 / 去设置”双操作，不叠加 Toast。
6. 日报模型从旧的 `deepseek-chat` 更新为官方当前的 `deepseek-v4-flash`。
7. 移除密钥使用 React 状态控制的应用内确认弹窗，确认后再调用 Tauri 命令。

## 5. 已知边界

- 保存验证会向 DeepSeek 发起一次极小请求，可能产生极少量用量。
- 自动化测试不读写用户真实 Keychain；Keychain 保存、替换和删除需在 macOS 应用内实测。
- DeepSeek 请求本身失败时仍沿用现有基础模板降级逻辑；本次只改变“未配置 Key”的交互。
