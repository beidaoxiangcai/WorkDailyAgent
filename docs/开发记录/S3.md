### 2.2 关键代码变更

**Rust 后端 — Tauri 命令 + 共享状态**

`lib.rs` 新增三个 `#[tauri::command]`：
- `query_events(date: String)` → `Vec<EventRow>`：查询某天事件，按 start_ts 倒序
- `set_paused(paused: bool)`：切换采集暂停状态
- `is_paused() -> bool`：读取当前采集状态

共享状态设计：
- `PausedState(Arc<AtomicBool>)` 注册为 Tauri State，供命令读写
- 同一个 `Arc<AtomicBool>` clone 传入 `Collector`，轮询循环每 tick 读取
- 暂停时 Collector 跳过 `poll_once`，但 flush 定时器继续运行（flush 缓冲中的已闭合事件）

`storage.rs` 新增：
- `EventRow` 结构（serde::Serialize，返回前端）
- `query_events(start_ts, end_ts)`：按时间范围查询，`ORDER BY start_ts DESC`

日期处理：`parse_day_range` + `days_from_civil`（Howard Hinnant 算法）把 "YYYY-MM-DD" 转为本地 0 点的 Unix 秒区间，避免引入 chrono 依赖。

**前端 — 三栏布局 + 时间轴页**

`App.tsx` 重写为：
- `layout` Grid 布局：56px 顶栏 + 200px 左导航 + 1fr 主区
- 顶栏：标题 + 状态点（绿=采集中/灰=暂停）+ 暂停/恢复按钮
- 左导航：今日时间轴 / 日报周报 / 设置（S4/S5 占位）
- 今日时间轴页：事件卡片列表，每卡 `时间 | 应用+标题 | 时长`，按时间倒序
- 每 10 秒自动刷新（与后端 flush 周期一致）+ 手动刷新按钮
- `formatTime` / `formatDuration` 工具函数（秒→HH:mm / 毫秒→人类可读时长）

样式（App.css / index.css）：
- CSS 变量驱动明暗主题（prefers-color-scheme）
- 卡片圆角边框、等宽字体显示时间/时长

## 4. 遇到的问题与解决

### 4.1【设计决策】SQLite 双连接

- 问题：`Storage` 持有 `Mutex<Connection>`，无法 clone；但 Tauri 命令（查询）和 Collector（写入）都需要访问数据库。
- 解决：开两个独立 Connection 指向同一文件。SQLite WAL 模式原生支持多连接并发（多读 + 单写），这是标准用法。AppState 持有读连接，Collector 持有写连接。

### 4.2【设计决策】状态栏菜单延后

- S3-T4 原计划做 macOS 菜单栏图标（红点/灰点 + 菜单）。
- Tauri 2.0 的系统托盘（SystemTray）需要额外配置 + 图标资源，且属系统级集成。
- 当前顶栏的状态点 + 暂停按钮已满足 F11 验收（暂停/恢复采集）。
- 决定将菜单栏图标留到 S5 打磨阶段，与权限引导、清空数据等系统级功能一起做。
