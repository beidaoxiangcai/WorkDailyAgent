### 2.2 关键代码变更

- `src-tauri/Cargo.toml`：引入 `tokio`（rt-multi-thread/macros/time/sync）、`objc2-app-kit`（NSWorkspace）、`core-foundation`（CFString），开启 `macos-private-api`。
- `src/collector/macos.rs`：
  - `check_accessibility_trusted()` → `AXIsProcessTrusted()`
  - `get_active_app()` → `NSWorkspace::sharedWorkspace().frontmostApplication()` 取 app_name/bundle_id/pid
  - `get_window_title(pid)` → `AXUIElementCreateApplication` + `AXUIElementCopyAttributeValue("AXTitle")`，失败返回 `None`（降级）
  - 外部 C 函数通过 `#[link(name = "ApplicationServices", kind = "framework")]` 链接
- `src/collector/mod.rs`：`Collector::run()` 用 `tokio::time::interval` 每 3s 调 `poll_once`；黑名单 bundle_id 命中则跳过；启动时打印权限状态。
- `src/lib.rs`：`setup` 中用 `tauri::async_runtime::spawn` 启动采集后台任务。
- `package.json`：scripts 改为 `node ./node_modules/.../bin.js` 直调形式（原因见第 4 节）。

## 4. 遇到的问题与解决

### 4.1【环境·高】项目目录名含冒号 `:` 导致两处工具链故障

项目所在目录名 `:.,mnbvcxz x xz:.hgfd】` 含冒号 `:`。macOS 多个 PATH 类环境变量以冒号作分隔符，导致路径被切碎。这个目录名看起来像是误输入产生的。

**影响 1：Rust 链接失败**
- 现象：`cargo build` 报 `failed to join paths from $DYLD_FALLBACK_LIBRARY_PATH` / `path segment contains separator ':'`。
- 原因：rustc 把含冒号的 `target/debug/deps` 路径加入 `DYLD_FALLBACK_LIBRARY_PATH`，被冒号切碎。
- 解决：`.cargo/config.toml` 中设 `build.target-dir = "/Users/chen/wda-target"`（无特殊字符的路径），绕过该问题。

**影响 2：npm 找不到本地二进制**
- 现象：`npm run dev` 报 `sh: vite: command not found`；npm 告警 `Path contains delimiter (":")`。
- 原因：npm 把 `node_modules/.bin` 加进 PATH，但该路径含冒号被切碎，vite 找不到。
- 解决：`package.json` 的 scripts 改为 `node ./node_modules/vite/bin/vite.js` 等直调形式，不依赖 PATH 查找。

**风险提示**：该目录名后续可能继续在其他工具上踩坑（如打包签名、某些 CLI）。**建议择机把整个项目迁到无特殊字符的路径**（例如 `~/work/工作日报Agent/`），可一劳永逸。本次为不阻断开发，采用上述绕过方案。

### 4.2【环境·中】crates.io 国内访问极慢/卡死

- 现象：首次 `cargo check` 拉取 crates.io 索引时，16 分钟 CPU 0.1% 卡死。
- 解决：`.cargo/config.toml` 配置 rsproxy 稀疏镜像（`sparse+https://rsproxy.cn/index/`），之后依赖下载与编译正常。

### 4.3【环境·低】沙箱不允许在 `~/` 下新建顶层目录

- 现象：`target-dir` 指向不存在的新路径时，`cargo run` 报 `.cargo-build-lock: Operation not permitted`。
- 解决：改用已 `mkdir` 预创建的 `/Users/chen/wda-target`。

### 4.4【已知·延后】Vite 拒绝服务 index.html

- 现象：`The request id ".../code/index.html" is outside of Vite serving allow list.`，疑似特殊字符路径导致 Vite fs.allow 校验异常，webview 可能显示空白。
- 处理：S1 交付物是采集内核（已验证），前端渲染属于 S3 范畴，届时在 `vite.config.ts` 配 `server.fs.allow` 修复。
